    3C — uninstall¶

    3C installs by copying into your repo and a small global CLI. That makes removal honest: it is a git revert plus a couple of local deletions. Nothing phones home, so there is no account to close and no remote state to purge.

    Installing or upgrading? Both routes — fresh install and update to latest, with the traps to avoid — are on Get started.

    White-label deployments¶

    A branded deployment (3c init --brand=<name>) re-points to a new upstream framework release with a dedicated command — this is distinct from reinstalling the npm CLI:

    3c upgrade --upstream-ref=<ref> --framework-version=<x.y.z>

    It preserves your BRAND_* config and refuses unsigned upstream refs.

    Uninstall¶

    Because 3C is copied into your repo under git, the cleanest removal is to revert the install:

    git revert <install-commit-or-PR-merge>

    That takes the standards, skills, agents, and hooks back out in one reversible step — the reversal posture the rest of the site promises. If you would rather remove the artifacts directly, delete what the installers wrote:

    • .claude/skills/, .claude/agents/, .claude/rules/ — the copied workflow skills, crew agents, and rule packs.
    • the PreToolUse hook entries in .claude/settings.json — the orchestrator + path-guard (git revert removes them if they were committed; otherwise edit the file).
    • CLAUDE.md (and the companion CLAUDE.local.md.example + the .gitignore lines init added).
    • the .3c/ directory — architecture and hook config plus all local state: events/*.jsonl telemetry, the local SQLite config, coaching/onboarding data, and dashboard.html.

    Then remove the global CLI:

    npm uninstall -g @kgn-git/3c

    There is nothing else to unwind. No daemon, no global workstation state, no remote account. The L2+ telemetry is gitignored local JSONL and SQLite under .3c/ — it never left your machine, so removing the directory removes the data. git revert of one PR restores the project exactly as it was.

    3C — coaching mode¶

    Coaching mode is the L2 feature that turns gate failures into mentorship moments. When a rule fails, the hook output no longer just tells you no — it tells you why, with a concrete example of the right shape, and a link to the rationale that produced the rule. The thing senior engineers normally do in code review, automated and immediate.

    This page is the operator's guide: what coaching is, how to activate it, how to write rationales for your team's rules, and what coaching deliberately does NOT do.

    What coaching mode is¶

    Concretely: when a pre-commit hook or post-edit validation fires and a rule violation is detected, coaching mode appends a delimited teaching segment to the failure output. Here is the actual shape (verified against the shipped implementation in src/validate/post-edit/coaching.ts):

    ——— 3c coaching ———
• import-order
  Why: imports should be ordered: stdlib, third-party, local — fewer merge conflicts in long-lived branches.
  Do: import { readFile } from "node:fs/promises";
  Docs: https://kgn-git.github.io/3C/
———————————————

    The bullet is the rule that triggered. Why: is the rationale you wrote. Do: is the first example from your rationale file. Docs: is the link to the ADR or incident that produced the rule.

    After 2 sightings of the same rule by the same developer, the segment goes terse — only the bullet and the reasoning, no example, no docs link. This is adaptive teaching: full detail until the developer has internalised the rule, then it gets out of the way. The threshold matches the shipped TERSE_AFTER = 2 constant in src/validate/post-edit/coaching.ts. Per-rule, per-developer state lives at .3c/coaching/<user>.yaml.

    How to activate coaching mode¶

    Coaching is ON by default. If .3c/coaching.yaml does not exist in your repo, coaching fires on every gate failure that has a recorded rationale. You do not need to do anything to turn it on.

    To disable globally for the whole repo, write:

    # .3c/coaching.yaml
enabled: false

    To disable per-user (for example: the team leads who already know the rules, while juniors still see coaching), write:

    # .3c/coaching.yaml
disabledUsers:
  - alice
  - bob

    The file is checked against the OS-reported user name. Add or remove names as the team evolves.

    How to write rationales¶

    Coaching is only as useful as the rationales you author. Each rule that should produce coaching output gets a sibling rationale file in .claude/rules/, co-versioned with the rule itself:

    # .claude/rules/import-order.rationale.yaml
reasoning: imports should be ordered stdlib, third-party, local — fewer merge conflicts in long-lived branches.
examples:
  - 'import { readFile } from "node:fs/promises";'
  - 'import axios from "axios";'
  - 'import { Widget } from "./widget.js";'
docLink: https://kgn-git.github.io/3C/

    The rationale file lives in git next to its rule. Edits propagate live — the next coaching invocation reads the current file content, no restart needed. This is the AD-01 git-native pattern: standards and their rationales travel together.

    If a rule has no rationale file, coaching will still record the rule fired, but the teaching segment will read (no rationale recorded yet) instead of a Why: block. That is the gentle nudge to the team's rule-author.

    On-demand lookup with /3c-explain¶

    When you are curious why a rule exists, but the rule has not fired yet, you do not have to wait for the gate to bite you. Run:

    /3c-explain import-order

    /3c-explain reads the same .claude/rules/<rule>.rationale.yaml files coaching mode reads, and prints the full reasoning + examples + docs link. Use it as the discovery path when a new team member is exploring the standards.

    What coaching mode does NOT do¶

    The honesty discipline carries over to this page: 3C under-claims and names limits.

    • Advisory only — coaching never blocks. The teaching segment is appended to advisory output (post-edit validation, the coaching layer in the pre-commit hook). The L1 pre-commit hook itself is blocking (lint / types / unit / secrets refusing the commit on failure); coaching is the added explanation, not the blocker. (NFR-REL-01.)
    • No AI rewriting. Coaching tells you what the right shape is via the Do: example. It does NOT auto-fix your code, propose a diff, or call back to Claude Code for a rewrite. Fixes are your call.
    • No opinion gating. Coaching only fires for rules with recorded rationales. If you have not written a rationale for a rule, coaching stays quiet on it — it will not invent a justification on your behalf. The team's rule library is the source of truth.
    • No telemetry egress at L2. Per-rule seen-counts live locally at .3c/coaching/<user>.yaml. They are NOT sent to a backend at L2. (At L3, the team-observability dashboard can roll up rule-firing patterns from local hook telemetry — see maturity model. At L2 your coaching history is your own.)

    Where this sits in the L2 surface¶

    Coaching is one of five DX additions L2 ships on top of L1. The companion features:

    • Standards Rationale Database — the structured "why" repository coaching reads from. Co-versioned .claude/rules/<rule>.rationale.yaml files.
    • /3c-explain <rule-id> — the on-demand lookup over the same rationale files.
    • Interactive Onboarding Guide (/3c-onboard-guide) — role-tailored variant of the onboarding skill, also surfaces rationales as part of role module sequences.
    • Personal Local Insights Dashboard — local-only .3c/dashboard.html showing which rules fire most for you and how often your changes pass on first try. The dashboard is fed by the hook telemetry that coaching also reads.

    If your team is upgrading from L1: coaching is the L2 feature with the highest signal for juniors. We recommend turning Drift Detector + Coaching on first, then layering the gate-tightening (Coverage Gate, Security Scan Gate) afterwards. See what L2 ships today for the full adoption order.

    What we're learning

    Teams that wrote rationales for at least half their rules before turning coaching on report the highest signal — coaching is only as good as the Why: you can articulate. The five-minute exercise of writing a rationale for each rule is, by itself, a useful retrospective check. If you are weighing coaching for your team, start a discussion.
